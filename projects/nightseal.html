NightSeal PQC

Plateforme de preuve d’intégrité post-quantique destinée à des environnements de sauvegarde de type Oracle RMAN / WriteOnce. NightSeal complète l’immutabilité du stockage par une chaîne de preuves cryptographiques vérifiables : inventaire, manifests chaînés, arbre de Merkle, signature ML-DSA, bundles de preuve, détection d’altération et rapports d’audit.

Docker ComposeFastAPIReact / VitePythonML-DSA-65pqcryptoMerkle TreePostgreSQLRedis

Problématique

Un stockage WriteOnce peut empêcher ou limiter la réécriture, mais il ne suffit pas à fournir une preuve cryptographique autonome et facilement auditable de l’état d’un grand jeu de sauvegardes.

NightSeal construit une preuve exportable de l’intégrité des fichiers et de son évolution dans le temps, avec une couche de signature post-quantique.

Stack & déploiement

  • Frontend React/Vite pour le dashboard et les workflows.
  • Backend FastAPI exposant les opérations de preuve et de vérification.
  • Worker dédié aux traitements asynchrones.
  • PostgreSQL 16 et Redis 7.
  • Déploiement complet via Docker Compose.

Chaîne de preuve

1. Inventoryscan du dataset et volumétrie
2. Manifestempreintes + état des fichiers
3. Merkleracine compacte du dataset
4. ML-DSAsignature post-quantique de la preuve
5. Bundlevérification, audit et reporting

Les manifests peuvent être chaînés dans le temps afin qu’un état précédent fasse partie du contexte cryptographique du suivant. Le workflow complet génère ensuite la preuve, la signe et vérifie automatiquement le bundle produit.

Cryptographie

Le moteur de signature propose un provider de démonstration HMAC et trois profils post-quantiques réels : ML-DSA-44, ML-DSA-65 et ML-DSA-87 via la bibliothèque pqcrypto. La configuration finale du projet utilise ML-DSA-65.

La vérification n’est pas déclarative : NightSeal vérifie cryptographiquement la dernière signature avant de considérer la chaîne de preuve comme prête.

Fonctionnalités développées

  • Inventory Scanner et scénarios de volumétrie RMAN-like.
  • Génération et chaîne temporelle de manifests.
  • Merkle proofs et signatures post-quantiques.
  • Proof bundles et vérification de bout en bout.
  • Tamper test, self-tests, historique d’exécution et timeline d’audit.
  • Benchmarks, rapports HTML/PDF et tableau de production readiness.

Architecture Docker

Interface & API

React/Vite fournit un dashboard couvrant l’inventaire, la chaîne de preuve, l’audit, les simulations et les rapports. Le backend FastAPI orchestre la génération et la vérification des artefacts.

Services & données

Un worker, PostgreSQL et Redis complètent l’architecture. Les jeux de données, manifests, signatures, rapports et historiques sont montés dans des volumes dédiés.

docker compose up -d --build Frontend : http://localhost:5173 Backend : http://localhost:8000 API docs : http://localhost:8000/docs

Production readiness

Le projet inclut son propre moteur d’évaluation : backend disponible, dataset accessible, chaîne de preuve fonctionnelle, manifest chain valide, provider ML-DSA actif et vérification de la dernière signature.

Cette logique permet de distinguer un prototype simplement démontrable d’un état dans lequel les contrôles cryptographiques critiques passent réellement.

Approche de falsification

Le Tamper Test modifie volontairement un artefact ou un élément couvert par la preuve puis rejoue la vérification. La différence entre « stockage immuable » et « preuve cryptographique d’intégrité » devient ainsi directement démontrable.

Limites actuelles assumées

Clés & contrôle d’accès

Les clés ML-DSA sont encore stockées sous forme de fichiers. Il n’y a pas encore d’intégration HSM/KMS, ni d’authentification API ou de RBAC.

Intégration entreprise

Le projet travaille sur des datasets RMAN-like et ne dispose pas encore de connecteur Oracle RMAN réel ni d’export SIEM. Ces points constituent les prochaines étapes naturelles d’industrialisation.
